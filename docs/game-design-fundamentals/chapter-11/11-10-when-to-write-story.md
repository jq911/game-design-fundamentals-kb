# 11.10 什么时候编写故事

> 来源：私人资料库 OCR 整理，摘自《游戏设计基础（原书第 3 版）》第 11 章。PDF 为扫描版，文字已做轻度校正，仍建议以后逐段人工复核。

## 原书内容整理

在概念设计阶段不能编写故事，只有在后来的详细设计阶段才能编写。这是我们在第7章中首次提到的、严格的规律之一。在概念设计阶段，你的工作是定义玩家的角色和在此角色下将体验到的游戏可玩性的种类。在概念设计阶段，你可以制作一个希望在游戏中包含的剧集或者关卡的列表，但是这时你还不能编写故事。（就像我们在上面讲述的那样，在计算整个工程的预算之前，你还需要设置好一个分支故事的结构，但是你不能开始编写故事本身。）

我们希望你等待一下再编写故事，因为只有在知道游戏将提供什么种类的可玩性之后，你才能知道玩家将会面临什么类型的挑战，以及她将被允许使用什么样的动作。甚至更重要的是，你不知道她不能采取什么类型的动作。编写一个包含很多不同种类动作的故事非常容易——但是程序员可能没有时间用软件来实现这些动作。如果你已经编写了一个故事，其中包含玩家化身骑马和步行两种动作，但是后来由于技术原因决定不实现骑马的动作了，那么你就浪费了很多时间。

编写故事的任务属于游戏设计中第二个主要阶段：详细设计阶段。你应该在设计了主要的游戏可玩性模式之后再开始编写故事，更好的时间是在设计出了你将提供的所有较重要的可玩性模式之后，因为那些模式的细节会告诉你玩家可以采用什么样的动作，以及他们将处于什么样的环境中。在现实中，编写故事和关卡设计是联系在一起进行的反复过程，因为关卡设计创造了玩家可以经历的时时刻刻的体验序列。如果游戏只在关卡之间呈现叙事，那么你可以使用大的间隔尺度来编写故事，在完成每一个关卡设计之后的时间段里编写，或者甚至在所有的关卡都设计完之后编写。但是如果叙事事件可以发生在关卡之内，那么你必须在设计关卡的同时编写故事。
