# 11.4 线性故事

> 来源：私人资料库 OCR 整理，摘自《游戏设计基础（原书第 3 版）》第 11 章。PDF 为扫描版，文字已做轻度校正，仍建议以后逐段人工复核。

## 原书内容整理

从计算机游戏设计的最早阶段开始，设计师都对创造出玩家可以影响情节并且改变结果的可能性很感兴趣。我们称那些玩家不能改变的故事为“线性故事”（linear story）；而那些玩家可以改变的故事为“非线性故事”（nonlinear story）。我们在下一节讲述非线性故事，本节先介绍线性故事。

电子游戏中的线性故事和任何其他媒体中的线性故事非常相似，在那里玩家不能改变情节或者故事的结局。然而，在游戏中，当玩家遇到一个故事时，他仍然面临着挑战，而且实际上这些挑战形成了故事本身的一部分。因而，游戏中的一个线性故事仍然是一个交互式故事，但是玩家的交互仅限于执行动作。很多游戏仍然使用这种形式。想想《半条命》和《星际争霸》：它们讲述的都是线性故事，故事的结局玩家都不能改变，但是玩家执行了很多作为故事一部分的动作。《星际争霸》各个任务之间的叙事块成为了玩家完成任务的奖励。

创造线性故事有很多优点，这也解释了为什么在20世纪90年代对非线性故事实验的恐慌之后，游戏产业在很大程度上又恢复使用这种习惯的原因。在游戏中使用线性故事也有缺点。下面是一些利弊用来在设计你自己的故事时进行考虑。

- 线性故事的内容要求较少。如果一个玩家只体验一系列固定顺序的事件，那么你只

需要创作出这些事件的素材。使用线性故事开发游戏会使用更少的时间和资金。

- 故事讲述引擎更简单。故事讲述引擎管理线性故事只需要跟踪一个情节事件序列就

可以了。因为玩家不能改变事件的过程，所以故事讲述引擎不需要记录玩家做出的重要决定，也不存在这些决定。如果你使用一个线性故事，那么故事讲述引擎用软件实现也就更简单了。测试故事讲述引擎需要大量的时间，所以许多开发者失败了。

- 线性故事更不容易出现漏洞和矛盾。如果不管玩家的动作是什么，事件序列都保持

不变，那么你就可以保证故事有意义。允许改变事件序列就引人了出错的风险，所以故事讲述引擎必须保证事件有意义。如果玩家在一个非线性故事的游戏中破坏了一辆汽车，那么故事讲述引擎就必须保证不会呈现任何关于未损坏的汽车的后继游戏可玩性或者叙事材料。如果不小心，你就可能引入电影行业称为连续错误的东西：在给定的前提事件下，因为叙事材料没有随着游戏事件而改变，所以东西的外表和它们应该具有的外表不同。线性故事不会产生这种风险。如果汽车损坏是故事的一部分，那么它就应该一直损坏。如果它没有被损坏，那么你不必给玩家提供损坏它的任何方式。

- 线性故事不允许玩家拥有戏剧性自由。在游戏中玩家可能有做很多事情的自由，但

却没有戏剧性自由（dramatic freedom），那就是说，他的动作除了让故事前进，不应影响其他的部分。就像我们在上一段提到的，如果故事始终要求有一个完整的汽车，那么游戏可玩性就不允许玩家损坏这辆汽车。我们会在本章的11.5.4小节中更为深入地讨论这个问题。

- 线性故事能驾驭更加巨天的情感力量。从创意的角度来看，这是它们最大的优势之

一。我们会在11.8.1小节中更详细地讨论这一点。注意，如果你希望讲述一个逻辑严密的线性故事，那么决定的结果就是你希望把所有的故事都作为旅行来看待（就像很多故事那样），参考11.7.2小节。
