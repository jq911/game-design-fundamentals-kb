# 11.9 带脚本的对话和对话树

> 来源：私人资料库 OCR 整理，摘自《游戏设计基础（原书第 3 版）》第 11 章。PDF 为扫描版，文字已做轻度校正，仍建议以后逐段人工复核。

## 原书内容整理

“自然语言”（natural language）指人类写作或者说话使用的普通语言。计算机科学家发明这个术语是为了把普通的人类语言和计算机（编程）语言做对比。使计算机理解人类语言——不管语言是作为对话还是作为指令出现——并做出合适反应，这个极度困难的问题已经困扰着人工智能研究者很多年了。最近的研究工作卓有成效，能够产生简单的问答系统，像苹果的Siri，但是对于电子游戏来说系统对自然语言理解的状态仍还有待提高，毕竟游戏中要实现真正的交谈。

作为游戏设计者，我们希望可以在游戏中包含自然语言，而同时又不用解决这个年代久远的研究问题。希望玩家可以参与到与非玩家角色（NPC）的交谈中，特别是在故事讲述游戏中。带脚本的对话（scripted conversation）允许我们近似地做到这一点。（注意关卡设计师经常使用被称为“脚本”或者“脚本事件”的技术，它们是一种不同的、不相关的现象。）

当进入一个带脚本的对话时，或者由玩家选择向一个NPC交谈或者一个NPC选择向玩家交谈，游戏都会进入为这种目的而创造的新的游戏可玩性模式中。所有其他正常的动作都不可用了。玩家不能说话或者用键盘打出他的对话，只能从一个目录中选择一个预先编写好的对话语句（如图11-4所示）。当玩家选择一个对话语句后，游戏让NPC做出相应的回应，然后系统给玩家一个新的菜单语句以便再次进行选择（有些可能是从NPC当前菜单扩展而来的）。这个过程来回地重复直到NPC不再和玩家说话或者玩家选择终止谈话。

在图11-4中，改编自《无冬之夜2》的玩家角色约书亚正在与一个名为Zaxis的角色交谈。上方窗口显示会话的最后几个交换。下面的窗口显示Zaxis的最新评论，以及一个供玩家选择的行列表。注意每个选项都伴随着一种说话方式：外交、虚张声势、恐吓等。如果大声说出这些话，玩家会对他的头像使用何种语调有想法。对不同NPC使用不同的方法可能效果更好。

如果NPC说了玩家以前没有听到过的词语，那么玩家可以要求更详细的解释，或者结束谈话，或者把主题转换到不同的话题。如果玩家第一次没有认真注意到某一点，那么可以提供有用的选项“再次告诉我关于……”，让玩家可以返回到刚才谈到的那一点并重新面对NPC的反应。为了结束谈话，玩家可以选择一句清楚地作为道别信息的语句（“谢谢你的帮助。也许以后我还会回来找你”），或者一个NPC可能偶然地通过一句像“我没有其他的东西要告诉你了”，或者“如果你再这样粗鲁的话，我就不跟你说话了”这样的语句来中断谈话。

### 11.9.1 对话树的结构

带脚本的对话可以使用“对话树”（dialog tree）设计，它是和已经讲述过的分支故事树相似的分支结构。在分支故事树结构中，它的节点或分支点代表着故事情节基于某些原因的分化——通常是玩家的决定。而在对话树结构中，每一个分支代表玩家可以选择的一个对话语句。与分支故事不同，这里的箭头可以朝上也可以朝下，因为玩家有时候希望重复他们的部分谈话。

树中的每一个分支点（或者节点）代表可以显示给玩家的一个不同的菜单。菜单包含供玩家选择的对话语句和NPC对每一个语句的反应。从箭头指向的每一个菜单项可以看到玩家将会看到哪一个节点，也就是哪一个新的对话选项目录。在脚本对话中，·计算机将当前菜单中的所有对话选项显示给玩家，并等待玩家选择其中一个。当玩家做出选择时，计算机执行NPC的响应，然后按箭头到下一个菜单，并在那里显示对话选项。当对话进行时，对话框会覆盖菜单后执行。

除了允许玩家与给定的NPC讨论各种主题之外，菜单系统允许玩家从各种不同的态度中进行选择，其中玩家所说的在本质上都是相同的事情，但这样能够将玩家自身投射到游戏中，例如积极的、恭顺的、流于形式的，或轻率的。NPC可以对每个短语进行不同的回应，无论他的个性如何。一个易于接近的角色可能会觉得一个轻率的回答更有趣，并可能选择向玩家揭示更多的信息，而如果对一个严肃的角色胡言乱语则可能会有所冒犯，并拒绝再次与玩家对话。（如果你采取了这种方法，而NPC信息对于故事情节又是至关重要的，则请确保过了一段时间之后再去找这位严肃的NPC角色对话，或者使用其他方式获得信息。）

在这个例子中，证人表现相当粗俗，只要玩家不要对他太敌对，他就帮助玩家。如果玩家采取过于激进的方法，那证人会要求找一位律师，以此结束对话。在这种情况下，玩家不会掌握证人所拥有的一些信息，因此玩家将不得不稍后重新访问证人或以其他方式找到证据。

- 图中的所有菜单并非都是让玩家以不同的口吻提出相同问题。有的会让玩家选择一

些问题来询问不同的主题。例如，在“询问证据”菜单中可以让玩家询问枪声、汽车或穿慢跑服的男人。如果证人不知道其中的任何东西，则箭头又回到同一菜单，让玩家可以询问不同的主题。

- 尽管在“关于汽车”菜单中的所有见证都会导向相同的位置（“跟随”菜单），但是

不同的选项仍然会向玩家提供一些不同的信息。

- 不是所有的问题都产生唯一的答案。在“酒吧访问时间”菜单中，礼貌和中立的

方法都从证人那里得到相同的答案。如果没有特殊的理由来区分它们，这是完全允许的。最后，注意在图11-5中，玩家可以拥有的无重复的最大对话次数是8。和分支故事一样，如果菜单继续分支而不折回，玩家很快就会得到菜单组合的爆炸式增长。在实际情况中，它们经常收敛或链接回到先前的菜单。

不幸的是，行业内没有用于设计对话树的标准符号或脚本系统。除了像图11-5一样创建一个带箭头的图之外，你可能会发现将对话写在文本文件中要更为容易，只需写“转到菜单【菜单名称]”以指示哪个菜单应该遵循对话反馈。如果这些因素会影响你设计对话，那你应该坐下来与程序员沟通，并设计出一套系统，使得你更容易创建对话，同时程序员也更容易理解；他们必须了解所有的因素，这样他们就可以编写实现这些因素的软件系统。当你打算这样做的话，确保你也为系统设计了一个测试计划，以免产生无意义的对话。

### 11.9.2 对话树的设计问题

当你创建一个对话树，你必须确保每一个对话树上每一个可能的分支都可以产生一组可信的对话。如果对话树很庞杂，那进行这样的验证就可能是一项繁琐而耗时的工作。如果有任何返回到对话中的较早时间点的箭头，你可能会发现必须要重写一些对话，以确保它第一次通过树和随后重新返回时的结果相同。在示例对话树中，一个方面肯定是不可信的：玩家可以一次又一次地询问“询问证据”菜单中的相同问题，并且证人总是给出完全相同的回应而从不抱怨。这是脚本对话的弱点，但它很常见，几乎成为一个游戏公约。玩家也会理解并忽略它。

#### 1. 条件分支机构和对话交互

对话树实际上很少像案例对话树那样看起来简单。图11-5显示了一个纯固定的对话，其内容不受核心机制的影响：玩家每次问询只产生一个来自证人的响应。但有时你想要其他因素来确定玩家有什么选择和NPC如何反应。NPC的响应不一定与玩家的单选择刚性连接。一些其他因素，例如游戏人物的魅力属性值，可能会影响NPC的响应。为了在对话树中指定这一点，你必须包括一种指示条件分支的方式：一些文本（例如），“如果化身的魅力大于12，给出响应A；否则给出反应B。”同样，包括外交技能或谈判技能的角色扮演游戏可以向具有高技能水平的玩家提供额外的菜单项，以便他们能够说出不熟练的角色不能做的事情。要在对话树中指定此项，您必须指示条件交换的存在，例如，“如果游戏角色的外交属性大于10，还包括.….”，并指定只有外交游戏角色才允许使用。

#### 对话树的设计工具

正如你在图11-5中看到的，在一个静态的媒介中很难记录对话树。因此本节介绍目前用来帮助你在计算机上设计对话树的各种工具，但并非所有工具都是免费的：

- articy：draft（发音为“artisydraft），来自Nevigo，是一款商业游戏设计软件，允

许你记录交互式故事和对话树以及人物对象和位置。其嵌套结构允许在屏幕上保持清晰的复杂系统。它仅适用于Windows系统。articy：draft可以将其内容导出到XML文件供你的编程团队使用，并且可以使用额外收费的方法：访问中间件，将你的艺术设计草稿直接并入游戏中。

- ChatMapper不如articy：draft那么强大，但它允许你在图形用户界面中构建对

话树，并以各种格式导出，包括偏好语音对话设计人使用的脚本。它是一款商业软件，在Windows下运行，可免费提供限量版。

- Twine是一款免费的图形工具，用于制作超文本游戏和对话树。它可以在OSX

和Windows上运行。Twine的简单格式使得非程序员也可以轻松使用。

- Scapple，来自literatureandLatte，是一个记录关联想法的便宜工具，虽然它不

是为了游戏开发而设计的。它可运行在OSX上，目前正在开发Windows版。

- Scrivener，同样来自literatureandLatte，是一款强大的适用于商业作家的工具，

可以帮助你记录许多想法、文件图片和其他内容组织，并实际写入你的文本。然而，它不是专门为对话树而设计的。

同样，带箭头的图表可能是也可能不是用条件内容记录脚本化对话的最佳方式。许多开发人员使用电子表格来记录脚本对话，因为电子表格程序可以根据需要轻松地添加行和列，同时保持文档看起来整洁，并且使用多个表格提供了更大的灵活性。如果你有一点编程经验，你会发现最简单的是写伪代码，通过它来与程序员讨论对话树。无论你选择什么方法，重要的是让程序员理解对话，以产生正确的结果。

#### 2. 另一种方法

另一种完全不同的方法是将对话机制看作是一种流程图（如图11-5所示），但是作为一个灵活的选项列表，不同的对话交互可以在不同的时间段添加或删除。这种方法不是创建交换的菜单，而是将每段对话分别作为单个项自写入，并给它命名或编号。记住，对话交互包括玩家所选择的问话和与之交谈的NPC的回应。每次对话交互后，你可以指定应将哪些新的对话添加到当前列表，哪些应该删除，而不是绘制通向新菜单的箭头。这样，就可以轻松地添加某些可永久保留在对话中的对话交互，而无需在每个新菜单中都进行记录。

例如，你可以添加一个“这就是我想要知道的一切”作为对话交互的结尾，当结束对话之后，自动跳回最开始的菜单，接着无论选择任何对话选项都不会删除该句。这将使玩家可以随时结束对话。主题第一次被提出之后，你可以添加一个“再告诉我….”的对话交互到菜单中，直到它被删除，玩家可以总是要求再次听到该主题。

开始操作：将对话交互1、2、3、4和5添加到菜单。对话交互1：玩家：「有礼貌的］“调查一宗犯罪需要你的帮助。请问你昨晚在3号大街上吗？”

回复：“是的，我正从那里的酒吧回家。”操作：删除对话交互1、2、3和4。添加对话交互6、7、8和9。

### 11.9.3 带脚本的对话的好处

虽然带脚本的对话迫使玩家只能说脚本上有的对话语句，但是它产生了一个看似真实的谈论和回答序列。它也给你了通过化身和NPC外表之外的东西来说明他们的个性。你也可以用此种方法来为他们赋予自己独特的个性，去写他们的故事。例如，《猴岛小英雄》中的英雄傻乎乎的盖博拉什——很少认真地对待任何东西的人一就使用谈话中的措辞来显示他是一个明智的人。角色的词汇、语法、方言、声音的语调以及重音（如果游戏使用录制的音频的话）都提供了重要的线索。

然而，带脚本的对话不仅仅只是向玩家提供信息的机制。它是故事真正的一部分，玩家的选择可以对游戏的进度产生明显的影响。如果一个NPC要求玩家委托给他一个有价值的秘密，那么玩家的决定，即是否告诉NPC，将会产生深远的影响。玩家必须在对NPC的价值进行评估的基础上选择回应，而你（作为设计者）必须提供NPC的价值的线索。

对于设计带脚本对话的不同方式的更深入讨论，我们建议你阅读克里斯：贝特曼（ChrisBateman）编著的《GameWriting：NarrativeSkillsforVideogames》（Bateman，2006）

的第14章：“DialogueEngines”。Bateman指出，大型的对话树可能难以处理，因此他提出了一些精简的建议。他无疑是正确的，但对于涉及各种主题的复杂对话，对话树会为你提供最全面的脚本能力。
