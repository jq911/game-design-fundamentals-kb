# 11.7 推进情节的机制

> 来源：私人资料库 OCR 整理，摘自《游戏设计基础（原书第 3 版）》第 11 章。PDF 为扫描版，文字已做轻度校正，仍建议以后逐段人工复核。

## 原书内容整理

在表现型媒体中，故事情节按照读者阅读或者显示的速度向前推进。在电子游戏中，故事讲述引擎推动情节的发展，但是没有固定的速度，而且每次向前推进时所使用的触发机制也不相同。不同的游戏使用不同的触发信号来告诉故事讲述引擎前进。在某些游戏中，一个挑战的成功或者失败推动情节前进。其他游戏中，化身在游戏世界中的旅程推动故事前进。在这样的游戏中，进入一个房间或者区域可以看作一个触发动作。在很少的一些游戏中，时间流逝单独推动情节前进，而不需要玩家做任何动作。在以下三个小节中，我们会更加仔细地学习这些技术。每一种方法都有它的优缺点，你必须选择使用一个最适合展现的故事的方法。

### 11.7.1 故事作为一系列的挑战或者选择

故事作为一系列的挑战或者选择在很多游戏中，情节随着玩家克服挑战或者做出决定而向前发展。在一个战争游戏或者驾驶模拟游戏中，完成一个任务或者通过一个关卡可以推进情节发展。这种系统非常适合那种根本不涉及行进或者行进本身不影响情节的游戏。在一个战斗飞行模拟中，玩家可以飞行到天空中的每个地方，但是这些行进都不影响故事。真正影响故事的是击落敌人的飞机或者被敌人射中。

《逆转裁判：复苏的逆转》是任天堂DS平台上的一款冒险游戏，也使用了这种机制。所有的游戏和故事事件都发生在一个限定的区域内——法院和其他一些当地的小地方。解决不同房子中的谜题可以推动情节向前发展。

有时候推动故事的触发不是解决一个挑战而是做出决定或者选择。角色扮演游戏经常让玩家做出重要的决定，例如是否加入一个特殊的协会，这些决定的结果都会对故事有很重要的影响。一旦玩家做出了决定一而且这些决定通常都是不能撤销的——情节就向前发展。

如果你要求玩家成功地克服挑战才能推动情节发展，那么故事讲述就应该是不平稳的，带着突然的开始和结束。玩家会感觉到在每次被一个挑战阻碍的时候故事就会停止，然后在他克服挑战之后故事就会重新开始。这在多故事的游戏中不算什么——总之，玩家只希望在一个较长的区间遇到故事讲述——但是在较少故事的游戏中这就显得有些呆板了。

冒险游戏和角色扮演游戏使用这种方法，但是它们把它和化身旅行一起作为触发情节前进的方式，这样在某种程度上可以减轻情节推进的机械感觉。它们把故事当作旅行来对待，这也是我们接下来的话题。

### 11.7.2 故事作为旅行

如果你的游戏涉及一个化身处于旅行中，也就是游戏中的很多动作都涉及把化身从游戏世界中的一个地方移动到另一个地方，那么你可以选择让化身的移动触发故事讲述引擎推动故事前进。使用这种方法的游戏经常在旅途中设置障碍，所以化身只有克服障碍才能自由地通过游戏世界到达一个新的区域。从实际效果上说，作为旅行的故事是由一系列挑战，有时候也会有一些选择——就像我们讨论的那样——加上一些旅行元素组成的：情节推进也可以由玩家纯粹到达一个区域而不是克服一个指定的挑战来触发。

把一个故事作为旅行呈现出以下好处：

- 它自动地提供了新奇性。因为玩家在通过游戏世界的过程中持续地看到新东西，因

此体验会保持新鲜和有趣。游戏得到了需要的用来保持玩家对游戏世界视觉外观感兴趣的新奇性，所以你不需要编写过多的新奇的戏剧性材料。

- 它允许玩家控制进度。大部分游戏允许玩家自己决定什么时候移动和什么时候静

止。除非对游戏可玩性强加一个时间限制，否则玩家就有了控制游戏进度的自由——在没有时间限制的情况下停下来思考角色和探索游戏世界。只有当玩家通过移动触发故事的时候，故事才向前发展。

很多游戏不仅仅使用旅行，而是特定地使用由约瑟夫·坎贝尔发现的“英雄之旅”的故事结构。某些设计师发现“英雄之旅”把挑战和旅行混合到一起特别适合用在单玩家的基于化身的游戏设计中。关于“英雄之旅”的更多信息，我们建议你阅读坎贝尔的《千面英雄》和克里斯多夫·佛格勒针对作家的著作《作家之路》。

如果你把故事作为旅行对待，并且把它制作成一个线性故事，虽然玩家可以在游戏世界中把化身移动回原来的地方，但是在她已经到过的地方就不会再发生更多的戏剧性事件了。由于这个原因，很多冒险游戏定期地要求玩家通过一个单向门——一个不能倒转的旅程机制，实际也可能采用单向门之外的其他东西。在《猴岛的秘密》中，英雄通过把自己放到一个大炮中发射来使自己离开船只来到陆地。一旦离开了船，就没有回去的路了。这种机制可以保证情节跟着化身向前发展。

计算机角色扮演游戏像例行公事般地把故事作为旅行对待，但是却使用高度非线性的故事。团队可以探索很大的区域，通常随心所欲地选择方向（虽然游戏将包含一种机制来阻正他们到达还不足以应付的区域）。其中绝大多数游戏都允许玩家重玩所有章节或者关卡，以获得更多的经验点。但这样做自然就扰乱了玩家将游戏当成一个连续故事来体验的感觉，因此这就是为什么它只是“可选”的原因。

### 11.7.3 流

少量的游戏会把故事作为戏剧来对待，它们按照自己的步调前进，使用时间的流逝推动情节。在这种情况下，核心机制不向故事讲述引擎发送触发来推动情节，相反，故事讲述引擎自己推动情节并向核心机制发送触发信号来说明什么时候应该提供某些游戏可玩性。

游戏《午夜陷阱》就是作为一个戏剧来操作的。故事按照真实的时间开展，不管玩家是否采取厂行动。它设置在一座郊外房子的宴会中，游戏安排给玩家的目标是保护宴会中的青少年不被入侵的一组怪物伤害。房子安装了一套安全系统，它们由闭路摄像机和陷阱组成。当玩家把它们设置好之后，这套系统就可以捕获和包含附近所有的入侵者。玩家通过安全摄像头观察不同的房间，如果一个怪物出现并试图伤害一个青少年时，玩家就会打开陷阱，这个青少年，就像恐怖电影中的那样，并没有意识到这种情况。《午夜陷阱》要求玩家根据宴会中的不同事件在各个摄像头之间转换并寻找怪物。如果玩家什么都没做而怪物抓走了其中一个孩子，玩家就会丢分。

《午夜陷阱》几乎完全由故事讲述组成，玩家除了在各个摄像头之间切换或者打开陷阱，没有其他的事情可做。因为不管玩家是否做了一些事情，故事都会向前发展，因此玩每个游戏通常都花费相同的时间。

更近一些的非商业游戏《劝架》也把故事作为戏剧呈现。在《Facade》中，玩家拜访一对老朋友并很快意识到他们的婚姻遇到了麻烦。玩家可以通过与他们进行对话来帮助解决问题——或者不能。整个游戏都发生在这对夫妇的公寓中，和《午夜陷》一样，即使玩家没有做任何事情，故事也会向前行进。但是玩家在游戏中的动作会对故事的方向和结局有着深远的影响。
