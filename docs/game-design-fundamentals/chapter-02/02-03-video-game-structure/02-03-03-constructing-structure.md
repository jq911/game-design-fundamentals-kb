# 2.3.3 构成结构

> 来源：私人资料库 OCR 整理，摘自《游戏设计基础（原书第 3 版）》第 2 章。PDF 为扫描版，文字已做轻度校正，仍建议以后逐段人工复核。  
> 关键词：游戏可玩性模式、shell 菜单、shell 屏幕、结构转换

## 原书内容整理

游戏可玩性模式和游戏的shell菜单共同构成了游戏结构。例如，在赛车游戏中，将赛车驾驶到修理站中会导致游戏从驾驶模式切换到停车模式；而当修理站的工作人员完成工作时，游戏又切换回驾驶模式。在驾驶时按下控制器上的“开始”按钮会弹出一个暂停菜单，等等。设计师需要为开发团队的其他成员记录这些详细信息。为了记录游戏结构，开始你可以列出游戏中所有的可玩性模式和菜单。你必须包含游戏何时以及为什么从一种模式或者菜单转换为另一种模式的说明：什么事件或者菜单选择会导致它的改变。每一种模式或者菜单描述都应该包含它可以转换的模式或者菜单列表，每一个可能的转换，还要有一个关于什么导致这次转换的记号。你可以通过简单地使用文本编辑器把它们列出来并记录所有的模式和菜单之间的关系。然而，这样结果不是很容易查找。我们推荐你使用流程板来记录游戏的结构，本章后面部分会讲述这种图表。正常情况下，游戏会在各种shell菜单中切换来回应玩家的动作。实际操作中，游戏从一种可玩性模式变为另一种模式来回应玩家的动作，或者是根据游戏要求的环境自动来改变。例如，足球游戏中，某些犯规动作会导致罚球，这时，一支球队中的一个运动员站在罚球点向球门踢球，而对方队伍中只有一个守门员，两队其他的球员都没有什么作用。这明显是和正常游戏不同的一种可玩性模式。它不是由特定的玩家选择触发的，而是由犯规规则的存在引起的。
