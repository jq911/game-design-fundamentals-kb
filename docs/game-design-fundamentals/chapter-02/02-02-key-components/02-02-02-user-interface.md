# 2.2.2 用户界面

> 来源：私人资料库 OCR 整理，摘自《游戏设计基础（原书第 3 版）》第 2 章。PDF 为扫描版，文字已做轻度校正，仍建议以后逐段人工复核。  
> 关键词：核心机制、用户界面、表示层、交互模型、视角

## 原书内容整理

通常从计算机软件就可了解用户界面的概念，但是在游戏中用户界面有更为复杂的功能。大部分计算机程序都是具有一定功能的工具：文字处理工具、网页浏览工具、绘图工具等。它们被设计得尽可能高效，以便能清晰地呈现用户的工作。游戏却不相同，因为玩家的行为不能假定都是很高效的，它们被游戏中的挑战所阻碍。大部分的游戏也向玩家隐藏信息，仅仅在玩家前行时才会显现出来。游戏的用户界面不仅要让游戏操作更方便，同时也要娱乐玩家。用户界面作为游戏核心机制和玩家间的媒介（见图2-1），它把核心机制产生的挑战（例如驾驶赛车）转化为在屏幕上显示的图像和从扬声器中发出的声音。它同样把玩家在键盘上的按键和对操纵杆的移动转化为游戏环境中的行动。

因为用户界面处于玩家与核心机制之间，所以它有时候也称为表示层（presentation layer）。用户界面的作用不仅仅是显示输出和接受输入。如果有故事，那么它还会表现出游戏的故事发展，并创建游戏世界的感官实体——游戏世界中所有的图像和声音，如果游戏装备有振动控制，那么游戏世界也会产生振动。游戏的所有艺术效果和声响均是用户界面的一部分，即游戏的表示层。游戏中用户界面的两个基本特征就是视角和交互模型，如图2-2所示。

#### 1. 交互模型

如我们曾经描述的，用户界面把玩家的按键转化为游戏中的行动。玩家的按键和作为结果的行动之间的关系由游戏的交互模型所规定。这个模型确定了玩家在游戏中如何制定她的意愿、选择和命令。特别地，它定义了在给定的任何时候她会采取什么样的行动。电子游戏采用了一定数量的标准交互模型，包括多处存在（multipresence）模型、基于化身的模型和竞争模型等。在多处存在模型中，无论什么时候，玩家都可以在游戏世界的不同地方采取行动，从“外面”进入“里面”。在基于化身的模型中，玩家是以一个在游戏中已经存在的人物身份出现的，玩家在游戏中所采取的行动也是通过这个人物来实现的。正如游戏中用户界面的可见部分在游戏过程中改变一样，游戏也不是只有一种交互模型，具体的交互模型要依赖于当时所发生的事情。在第12章中将对交互模型进行深入讨论。

#### 2. 视角

如果一款游戏包括模拟的物理空间或游戏世界，那么几乎肯定它会使用图像向玩家显示这一空间。用户界面的显示是一个从特定角度或视点（可以移动）进行观察而得到的空间。设计师想象通过一个假想的相机来创造出玩家看到的图像。这个控制假想相机行为的系统被称为相机模型。要定义相机模型，可以先站在玩家的角度考虑应该如何查看游戏世界，然后再在设计文档中指定一个系统让程序员对此专门进行编程。相机模型可以是静态也可是动态的。早期的街机游戏和如今的许多小游戏都使用静态的相机模型：相机总是从固定的角度显示虚拟空间。而在动态模型中，相机会根据游戏世界中玩家的动作或事件移动。动态相机模型需要付出更多的努力来设计和实现，但它们会使玩家的体验更加舒爽和流畅。如果游戏中没有虚拟空间（例如它是一个商业模拟游戏，画面主要由数字和图表构成），此时相机模型便不适用了，而且你必须在设计文档中对游戏屏幕上出现的各种元素做出详细的解释。最常使用的视角有呈现3D游戏世界的第一人称和第三人称，以及呈现2D游戏世界的自上而下、横向滚轴和平视图。我们在第8章中会讨论游戏世界维度的问题，在第12章中叙述不同视角的优点。

#### 没有图形的游戏

早期大多数计算机游戏是基于文本的，通过附属于主机的打印终端进行操作。只有文本显示的游戏依然以智力题和小游戏的形式存在，特别是在手机等这样的小型设备上。交互小说（interactive fiction）（只有文本的冒险游戏）——在商业类别中消失已久，但是它依然在有某种爱好的小团体中盛行。盲人玩家能够使用文本语音合成器玩文本游戏。还有一小部分针对盲人的处于试验阶段的语音游戏。
